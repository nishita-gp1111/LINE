# 複数ブラウザーのトーク自動更新

## 原因と修正

従来は受信メッセージの通知が来たときだけトーク画面を再取得していたため、別の担当者の送信・配信履歴・内部メモ・対応状況の変更だけでは更新されなかった。また、新着通知の初回確認は過去通知を抑制するための基準設定だけなので、画面取得後から初回通知確認までの変更を見逃す場合があった。

- トーク画面は通知の有効・無効に関係なく、表示中に約1分間隔で変更を確認する（通信・DBの応答時間は別）。
- 変更がある場合だけ画面のサーバーデータを再取得する。ブラウザー全体は再読み込みしない。
- 入力途中の本文・内部メモ・選択済みファイルは保持する。自動送信はしない。
- 最初に表示したトークをURLで固定する。別のお客様の新着で一覧の並びが変わっても、入力中のトーク・送り先を勝手に切り替えない。検索条件も維持する。
- タブ復帰・ウィンドウ再選択・ネットワーク復帰時にも最新状態を確認する。
- 非表示タブの定期確認は停止。復帰時に取り直す。非表示・フォーカスのないトークは自動既読にしない。
- 一時的な通信失敗・認証確認401は約1分後に再確認する。失敗時に確認頻度を上げない。401の場合は再ログインを案内する。一時的な認証基盤障害からも復帰できるよう、タブ復帰・「今すぐ更新」でも再確認する。認証されるまでデータは取得しない。
- トーク件数の下に同期状態と「今すぐ更新」を表示する。
- 同一時刻の更新や遅れて確定するDB更新も補完するため、変更が見つからない場合も表示中は約5分間隔で再取得する。通常の受信・返信は次の約1分の確認で反映する。

## 2026-10-29 利用量削減

同期5秒・通知8秒の二重確認を、両方とも60秒に変更。通知は非表示タブで300秒間隔（デスクトップ通知は継続）、トーク同期は非表示中停止する。
表示中の定常的な確認リクエストは1タブ当たり毎時約1,170回から120回へ約90%減少する計算。初回・操作時の再取得・ページング・ネットワーク待ちを除く。CPU時間や料金の90%削減を実測・保証するものではない。
変更がない場合の補完的な画面再取得は毎分から5分間隔へ削減。「今すぐ更新」と本人の送信後の即時表示は維持する。
このコード変更はVercelの既存の利用枠停止を解除しない。公開先の停止とデータ消失は別であり、停止中の受信イベント保存状況も別途確認が必要。

## 実装・保護

`GET /api/inbox/sync` はログイン必須、`private, no-store`。ログイン中のorganizationでmessages / conversations / contacts / conversation_notesの更新日時とID、および本人のconversation_read_statesだけを確認し、SHA-256リビジョンのみを返す。本文・LINE User ID・トークンは返さない。

各問い合わせは最新1行の小さいメタデータに限定する。本文や会話詳細を定期的に全件取得しない。DBテーブルの規模によってはupdated_atの検索索引を別途検討する。

ページの変更基準はページデータ取得前に採取し、画面に新しいサーバーデータが反映されるまで基準を進めない。これにより、描画中の変更や画面再取得失敗があっても次の確認で再試行する。

新しいmigration・環境変数・外部サービスは不要。LINEへの送信・Webhook設定・機能フラグは変更しない。

## 検証

- Unit: 認証・organization/profile分離・例外の非露出・取得列と件数の制限・マイクロ秒精度・受信/送信/送信結果/メモ/対応状況/送信取消。
- E2E: 独立した2ブラウザーで同じアカウントにログインし、片方からの返信・メモ・対応状況が他方に自動反映されることを確認。
- E2E: 下書き本文・メモ・未送信PDFの保持、全体再読み込み0回、勝手な送信0回、背景既読0回。
- E2E: 初期表示のトーク固定、別のお客様の新着でも相手・下書きを保持、検索後も条件を維持して再固定。
- E2E: 変更なしで全画面データ再取得なし、503からの自動復帰、非表示からの復帰、focus/online、「今すぐ更新」、401の案内と認証復帰後の再同期。
- E2E: PCおよび390px幅での表示確認。
- E2E: ブラウザー時計で実際の60秒タイマーを進め、59秒で問い合わせなし、1分で問い合わせ、非表示で同期停止、通知は5分に減速、エラー時も高速再試行なし、変更なしの全画面再取得は5分間隔であることを確認。

E2Eの送受信はローカルMock環境のみ。顧客へのLINE送信や本番データの作成は行わない。
