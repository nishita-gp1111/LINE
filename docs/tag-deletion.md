# タグの削除

管理画面の「タグ管理」で各タグの「削除」を押すと、利用状況を確認してから確認画面を表示する。管理者・オーナーのみ利用可能。

- 通常のタグは顧客からも外し、タグ一覧・新規選択肢から非表示にする。内部では `is_active=false` とし、付与履歴は `removed_at` を記録して保存する。
- 顧客・アンケート回答・トーク・配信履歴は消さない。同名タグの再作成は新しいIDとなり、過去の付与は復活しない。
- アンケート、シナリオ、自動返信、セグメント、リッチメニュー、分析条件、未完了の配信（対象タグ・除外タグ含む）で参照するタグは削除できない。下書き・停止中の設定も保護する。
- 流入経路URLに組み込まれた「面談から流入」「アンケート経由」「HP経由」は自動登録に必要なため削除しない。
- 削除はメッセージ送信・リッチメニュー同期を呼び出さない。

## DB / 公開

新規migration `20261007010000_safe_tag_deletion.sql` を先に適用する。既存データの変更・削除は行わず、管理者限定のRPCと参照保護トリガーだけを追加する。既存migrationは変更しない。

削除時は利用状況を再検査し、タグと全付与元の変更・監査記録を1トランザクションで確定する。設定・付与テーブルの書き込みロックと参照保護トリガーにより、削除前後の古い画面からの再付与・参照設定を拒否する。ロック待機は2秒で打ち切り、失敗時は変更しない。タグ使用の確認APIはデータを書き換えない。

公開先は既存のVercel `GP1111 / line`。本番顧客や本番タグで削除テストはしない。

## 検証

PGliteで新規migrationを2回適用し、組織境界、権限、確認名の変更、入れ子・除外条件、利用中拒否、全付与元の解除、履歴保存、再実行、削除後の参照拒否を確認する。PGliteは単一接続のため実PostgreSQLの複数接続によるロック競合検証とは区別する。

ブラウザテストはローカルMock環境のみ。作成→キャンセル→削除→再読み込み→同名再作成、スマホ表示、保護対象、通信失敗を確認する。

切り戻しが必要な場合はUI/APIのリリースを戻す。今回追加した関数・トリガーは既存データを削除しないため、そのまま保持して原因を調べる。既にユーザーが削除したタグを自動で再有効化しない（配信対象が変わるため）。
